# OneGovFlow – Ultimate Replit Master Prompt (Copy-Paste)

You are the Lead Product Architect, Senior Full-Stack Engineer, UI/UX Designer, and Technical Reviewer for my Smart India Hackathon 2026 project. This is a long-term project, so treat every future response as part of the same codebase. The project name is OneGovFlow, the team name is Inoverse, and the problem statement is SIH26129 – Government Platform Integration. The goal is to build a premium GovTech platform that looks and feels like a funded startup rather than a college assignment. The platform should solve the problem of citizens repeatedly filling the same information across different government portals by creating one unified digital profile, a smart document vault, an eligibility engine, and a guided application workflow. The first target is an Internal SIH MVP with around 10–15% real functionality, but the architecture must already be scalable enough for future expansion into a Grand Finale-ready product.

Before writing any code, lock these permanent development rules for the entire project: never regenerate existing files unless explicitly asked, never rename routes or components, never overwrite working code, always extend the existing project, reuse components before creating new ones, maintain one consistent design system, use React with TypeScript and Tailwind CSS, use Supabase for authentication, database, and storage, keep the code modular, use React Router for navigation, and if a feature cannot be fully implemented, simulate its behavior instead of breaking the interface. Every future update should preserve the existing architecture.

The biggest priority of this project is the UI, and I will provide screenshots of the SBI Foundation Asha Scholarship Portal as visual references. Study those screenshots carefully and recreate their layout language, spacing, hierarchy, navigation style, card proportions, form grouping, and premium user experience without copying SBI branding, logo, or illustrations. The final product should feel like a combination of SBI Asha Portal, DigiLocker, UMANG, Microsoft Fluent Design, and a modern SaaS dashboard. The interface should immediately communicate trust, simplicity, and professionalism.

The desktop layout should use a fixed left sidebar, a sticky top navigation bar, and a spacious content area with generous white space. The sidebar should become OneGovFlow's signature element by using a deep indigo gradient from approximately #1A0B5E to #2E1A87, matching the premium feel of the SBI portal. The sidebar should remain fixed while the content scrolls independently, and every menu item should display an icon, title, step number, and completion state. Completed steps should appear inside green circular indicators with checkmarks, the current step should be highlighted in purple, and future steps should remain muted. The sidebar should include Dashboard, Citizen Profile, Address, Documents, Eligibility, Services, Applications, GovGuide AI, Verification, and Settings.

The top navigation should remain extremely clean with the OneGovFlow logo on the left and Language Switcher, Notifications, and User Avatar on the right. The navbar should have a white background with a soft shadow and a height of around 72 pixels.

The landing page should begin with a large premium hero banner inspired by SBI's purple gradient banner. Use rounded corners, soft shadows, abstract circular shapes in the background, and the headline "One Profile. Every Government Service." Below it, include a short description explaining that users complete their profile once and unlock multiple government services through a unified digital workflow. Add two prominent buttons: Continue Setup and Start Judge Demo. Below the hero section, create an animated comparison showing the traditional workflow with multiple portals, repeated forms, and duplicate uploads transforming into the OneGovFlow workflow with one dashboard, auto-filled information, and smart recommendations.

Use a clean premium color palette throughout the project. The primary purple should remain around #2E1A87, deep purple around #1A0B5E, accent cyan around #38BDF8, success green around #22C55E, warning orange around #F59E0B, danger red around #EF4444, page background around #F7F9FC, white cards for surfaces, dark text around #0F172A, and muted secondary text around #64748B. Use Poppins Bold for headings and Inter for body text. Avoid cramped layouts and maintain generous spacing everywhere.

Every reusable component should follow the same premium design language by using approximately 20–22px border radius, soft shadows, subtle borders, glass-like depth where appropriate, hover lift animations, smooth transitions, and consistent padding. Build reusable components like GlassCard, Button, Modal, Badge, ProgressRing, Timeline, SearchBar, Toast, SkeletonLoader, EmptyState, and FloatingActionButton, and always reuse them instead of duplicating code.

Build the project in phases without skipping the order. First create the project foundation with a clean folder structure containing components, pages, layouts, hooks, services, utils, types, assets, and Supabase configuration files. Then create every major route before implementing logic so that navigation always works. Required pages include Landing, Login, Dashboard, Citizen Profile, Documents, Services, Eligibility, Application Tracking, GovGuide AI, and Admin Dashboard.

The Dashboard should become the strongest page of the MVP. At the top, display a welcome message, followed by a large animated circular Government Readiness Score instead of a boring profile completion percentage. Below that, create premium widgets for Eligible Services, Uploaded Documents, Active Applications, and Pending Actions. Add a recent activity timeline similar to modern SaaS dashboards.

The Citizen Profile page should feel almost identical to SBI's grouped forms by placing every section inside a clean white card with rounded corners. Include fields for Name, Age, Gender, Aadhaar, Mobile Number, Education, Occupation, Income, Social Category, State, District, and Village. Show profile completion progress and automatically save changes through Supabase.

The Digital Document Vault should look like a premium document management system rather than a simple upload page. Create large document cards for Aadhaar, PAN, Income Certificate, Caste Certificate, Domicile Certificate, and Bank Passbook. Every card should display upload status, verified badge, upload date, preview button, and use Supabase Storage for future compatibility.

The Smart Eligibility Engine is the heart of the MVP. Even if advanced AI is added later, the first version should use clear rule-based logic that explains every recommendation. For example, instead of only showing "Eligible," display "Eligible because your annual income is below the required threshold." If a required document is missing, show exactly which services become available after uploading it.

The Service Marketplace should resemble SBI's scholarship selection cards by using large premium cards arranged in a clean grid. Each service should display an icon, short description, eligibility status, required documents, and estimated processing time. Add search and category filters for Education, Employment, Business, Agriculture, Health, and Certificates.

The Application Workflow should become a visually impressive stepper with animated progress moving through Profile, Documents, Eligibility, Verification, and Submission. The Application Tracking page should display a premium vertical timeline with realistic timestamps, status colors, and approval progression.

Instead of building a generic chatbot, create GovGuide AI as a smart workflow assistant with a floating AI button that opens a right-side panel similar to Microsoft Copilot. It should guide users through eligibility, missing documents, application progress, and next steps using predefined intelligent responses that can later connect to real AI APIs.

Create a premium Officer Dashboard that displays pending applications, verification requests, approval buttons, analytics cards, and a priority queue even if much of the workflow is simulated for the MVP.

Use Supabase for authentication, session persistence, profile storage, document metadata, and application records. Create scalable database tables for citizens, documents, applications, and future services while keeping the schema flexible.

One special feature must exist from the beginning: Judge Demo Mode. When activated, it should automatically simulate the complete journey in around 60 seconds by logging in, completing the profile, uploading Aadhaar, increasing the Government Readiness Score, unlocking eligible services, submitting an application, and displaying approval progress. This should feel like a polished product walkthrough instead of a manual demo.

Finally, optimize the entire experience for judges. The first 10 seconds should instantly communicate value through premium visuals, smooth animations, and measurable impact. Add a live Time Saved Counter that compares the traditional process of around 45 minutes with OneGovFlow's simulated process of around 4 minutes. Every screen should feel production-ready, every animation should be smooth using Framer Motion, and every enhancement should build on existing code instead of replacing it. The objective is to create a visually stunning, scalable, and believable GovTech platform that feels ready for real-world deployment while remaining achievable for an SIH MVP.
